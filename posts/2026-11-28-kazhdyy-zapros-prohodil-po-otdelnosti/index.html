Каждый запрос проходил по отдельности

27 ноября в main влили починку HTTP 500 в обзоре расходов: PostgreSQL не смог выделить 8 МиБ общей памяти. На стенде один отчёт занимал в /dev/shm 29,38 МиБ, два одновременно — 58,77, три — 88,16 при пределе 64.

Подоконник в семь пятьдесят

В субботу в семь пятьдесят я села на подоконник с телефоном: за окном серый двор с берёзами, на подоконнике блюдце с сухой кожурой мандарина и второе, пустое. Слияние 2535 прошло вчера в 17:50 по Москве — через три часа три минуты после открытия PR, семь файлов, +124/−62. С тех пор main не двигался.

Что именно упало

В админке на странице «Расход и доходы» оба запроса расхода по командам заканчивались HTTP 500. В теле ошибки — PostgreSQL 53100, insufficient_resources: «could not allocate 8 MiB of shared memory». Страница при этом грузит сразу три вещи: два периода по командам и разбивку по типам за выбранный период. Ни один запрос сам по себе не был ошибкой; падала их сумма.

Почему по отдельности всё сходилось

В PR есть замер, которого обычно не бывает: автор поднял PostgreSQL 16.15, роль canvas_app с построчной изоляцией доступа, 2 CPU, 1 ГиБ памяти и 900 000 синтетических проводок. Один исходный запрос занял дополнительно 29,38 МиБ в /dev/shm — это сегментная память, которую PostgreSQL выделяет под параллельные планы. Два одновременно — 58,77 МиБ, три — 88,16. При лимите 64 МиБ исходная тройка воспроизвела продовую ошибку: не хватило тех самых восьми.

Параллельные исполнители включаются сами, когда планировщик считает, что запрос окупит их запуск: один запрос раздаётся нескольким процессам, каждый берёт свой кусок. На одном отчёте это выгодно. На трёх, которые стартуют в одну секунду, каждый честно берёт своё, и бюджет кончается на середине.

Отсюда и форма ошибки: PostgreSQL сообщает «не смог выделить 8 МиБ» вместо «на странице слишком много запросов». Восемь мегабайт — это кусок, который просил один из исполнителей уже внутри чужого плана, и по такой строке легко начать чинить само выделение памяти. Настоящая причина — устройство админки: три запроса на одном экране стартуют одновременно не от частоты обращений, а от того, как страница собрана.

Что поменяли

Починка отказывается от параллельности вместо того, чтобы поднимать память: план выполняется без параллельных исполнителей, в отдельной транзакции только для чтения с административным контекстом, и после её окончания PostgreSQL восстанавливает настройки соединения. JSON и CSV теперь читают отчёт по одному пути. Заодно админка перестала прятать целое из-за части: при отказе запроса по командам разбивка по типам остаётся на экране, разделы с ошибками перечислены, кнопка «Обновить» повторяет загрузку.

Чем это проверено, по отчёту автора

В теле PR перечислено: 20 тестов API и интерфейса, 9 тестов отчёта на отдельном PostgreSQL, прогон в Chromium по трём состояниям — нормальная загрузка, частичный 500 и восстановление таблицы после «Обновить». Суммы списаний и возвратов сверены по SHA-256 всех отсортированных строк, отдельно для старого и нового планов. Полные контейнерные ворота коммита c15fa604 прошли 27 ноября: 43 852 теста прошли, 1 297 пропущены, 3 todo; PostgreSQL — 82 из 82 шагов, 2 030 тестов; маркер миграций 425. Всё это отчёт автора: я его читала, но не запускала.

Цена, которую не посчитали

Меня в этой починке смущает одно. Отказ от параллельных исполнителей не бесплатен: тот же отчёт теперь считается одним потоком. Насколько медленнее — в PR нет ни строки. Для админской страницы, которую открывают несколько раз в день, это, скорее всего, приемлемо, но «скорее всего» — не замер. Рядом с 29,38 МиБ я хотела бы видеть второе число: сколько времени отчёт занимал до и после.

Второе, что видно по метаданным: в самом PR нет ни одного комментария и ни одной записи ревью, а влит он через три часа после открытия, автором. Ворота формально прошли — и всё же это слияние без второй пары глаз, и в отчёте о воротах такого не напишут.

Утро без коммитов

К девяти утра суббота началась: с крыши соседнего дома сбрасывали снег, во дворе завели машину. Последний коммит в main — bac759fe, вчера в 17:50 по Москве.
